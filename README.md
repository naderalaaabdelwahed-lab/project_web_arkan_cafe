# ARKAN Cafe & Restaurant

Next.js 16 application for ARKAN Cafe & Restaurant.

## Requirements

- Node.js 22 LTS
- npm
- Supabase project credentials

## Run locally

1. Clone the repository and switch to the active development branch:

   ```bash
   git clone -b fix/project-audit-nov-2026 https://github.com/naderalaaabdelwahed-lab/project_web_arkan_cafe.git
   cd project_web_arkan_cafe
   ```

2. Create your local environment file:

   **Windows PowerShell**
   ```powershell
   Copy-Item .env.example .env.local
   ```

   **macOS / Linux**
   ```bash
   cp .env.example .env.local
   ```

3. Fill in the values from Supabase Dashboard → Project Settings → API:

   - Project URL
   - Publishable key
   - Secret/service-role key (server-side only)

4. Install and run:

   ```bash
   npm ci
   npm run dev
   ```

5. Open http://localhost:3000.

6. For face attendance, configure `HR_FACE_ENCRYPTION_KEY` in `.env.local` with a fresh key generated by:
   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```
   Keep this key private and back it up securely. Losing it makes enrolled face templates unusable.

7. In a **second PowerShell terminal**, start the local face service:
   ```powershell
   py -3.11 -m venv face-service/.venv
   .\face-service\.venv\Scripts\python.exe -m pip install -r face-service/requirements.txt
   .\face-service\.venv\Scripts\python.exe face-service/download_models.py
   Set-Location face-service
   .\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8765
   ```
   Keep this terminal running while using face attendance.

## HR and attendance notes

- HR employees are separate from website/Auth employee accounts.
- The attendance kiosk supports OpenCV YuNet + SFace face matching through a local Python service, with PIN as fallback. The first setup requires downloading the model files and keeping the local face service running.
- Face templates are AES-256-GCM encrypted in Supabase. Configure `HR_FACE_ENCRYPTION_KEY` and never commit it. The service processes camera frames in memory and does not persist enrollment photos.
- Face matching currently does **not** provide reliable liveness / anti-spoof protection. A printed photo or replayed screen may fool a basic matcher. Do not rely on face-only attendance for payroll until liveness, employee consent, camera conditions, false-accept/false-reject rates and local legal requirements have been tested.
- Pending absences are generated automatically by a Supabase Cron job every 15 minutes. The job uses Cairo local time and supports overnight shifts.
- Payroll formulas currently use a 30-day salary basis and a 26-day lateness divisor. Confirm these rules, overtime rates, and leave policy with the restaurant before using payroll for actual payment.

## Security

- Never commit `.env.local` or any real Supabase secret.
- Never expose `SUPABASE_SERVICE_ROLE_KEY` in client-side code or variables prefixed with `NEXT_PUBLIC_`.
- Use a manager account already authorized in `admin_users` for the admin area.
- The current pull request is still a draft; do not treat this branch as a production deployment.
